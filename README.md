# Gains Log — frontend

Static frontend for the Gains Log gym tracker. This used to be a Netlify
site with its own Netlify Functions backend (Netlify Blobs); that backend
now lives in a separate repo, [`gains-log-backend`](../gains-log-backend),
so it can be hosted anywhere with a persistent process (Railway, Render, a
VPS, etc.) instead of relying on Netlify Blobs — which had a noticeable
read-after-write lag (a check-in would briefly show as unchecked after a
refresh).

## Setup

1. Deploy `gains-log-backend` first and note its public URL.
2. Edit `public/config.js` and set:
   ```js
   window.GAINS_LOG_API_BASE = "https://your-backend-url.example.com";
   ```
3. Deploy this repo to Netlify (or any static host). Netlify runs
   `npm run build` (see `netlify.toml`) to generate the Tailwind CSS, then
   publishes `public/`. On other hosts, run `npm ci && npm run build` first.

## Local development

```bash
npm install
npm run dev      # rebuilds public/css/styles.css on every change
npm run serve    # in a second terminal
```

(or any static file server) — just make sure `public/config.js` points at a
running backend first.

> The app uses native ES modules, so it must be served over HTTP — opening
> `index.html` straight from disk (`file://`) won't work.

## Project structure

```
public/
├── index.html            # markup only
├── config.js             # deployment config (backend URL)
├── css/styles.css        # generated by Tailwind (gitignored)
└── js/
    ├── main.js           # entry point: wires components, restores session
    ├── constants.js      # gym days, poll interval, storage keys, grid views
    ├── state.js          # shared app state + subscribe/notify
    ├── api.js            # typed wrappers around the backend endpoints
    ├── storage.js        # session/localStorage helpers
    ├── sync.js           # loading data + polling the backend
    ├── render.js         # renders every section from state
    ├── domain/           # business rules (schedule, stats, penalties)
    ├── utils/            # date + formatting helpers
    └── components/       # one module per UI section
src/
└── styles/main.css       # Tailwind entry: theme tokens + shared utilities
```

## Styling

Styles use [Tailwind CSS v4](https://tailwindcss.com). Colours are CSS
variables in `src/styles/main.css` (with light/dark variants) exposed to
Tailwind as `bg-surface`, `text-dim`, `border-line`, `bg-accent`, etc.
Repeated patterns (`card`, `btn-primary`, `btn-secondary`, `field`, …) are
defined there with `@utility`. Component state is expressed with `hidden`,
`aria-pressed` and `data-*` attributes and styled via Tailwind variants
(`aria-pressed:bg-accent`, `data-[state=rest]:bg-surface-2`).
